# MVP v1 验收场景

> 第二阶段后端开发必须遵循 TDD：先把相应场景写成失败测试，再实现代码，最后重构。真实联网和真实模型测试单独标记，不代替可重复运行的假实现测试。

## A. 输入与分类

### AC-01 一句话问题

- 给定：输入 `RAG 是什么？`，默认配置。
- 当：创建闯关。
- 那么：输入被识别为 `QUESTION`，允许提交并生成 5 道题。

### AC-02 用户原文

- 给定：一段完整概念说明，没有显式问题。
- 当：创建闯关。
- 那么：输入被识别为 `USER_SOURCE`，用户原文是主要证据。

### AC-03 混合输入

- 给定：用户原文后附带明确学习问题。
- 当：创建闯关。
- 那么：输入被识别为 `HYBRID`，题目保留目标并可追踪到原文或官方补充来源。

### AC-04 无产品级字数限制

- 给定：一句正常问题，或需要分块处理的长文本。
- 当：前端校验与 API Schema 校验。
- 那么：不因字符数量不足或过多而拒绝；只有全空白输入返回 `EMPTY_INPUT`。

### AC-05 安全输入

- 给定：包含身份证号、密码样式、API Key、Prompt Injection 或不允许内容的输入。
- 当：创建闯关。
- 那么：返回对应 422 错误，不调用出题流程，不在响应和日志中回显敏感值。

## B. 来源与题目

### AC-06 官方来源模式

- 给定：`QUESTION` 输入，没有用户原文。
- 当：创建闯关。
- 那么：使用官方来源；找不到可靠来源时返回 `RELIABLE_SOURCE_NOT_FOUND`，不使用无引用模型常识出题。

### AC-07 用户原文优先

- 给定：`USER_SOURCE` 或 `HYBRID` 输入。
- 当：同时存在用户原文和官方补充。
- 那么：二者来源类型分别标记为 `USER_TEXT` 和 `OFFICIAL_WEB`，不会混写来源。

### AC-08 题目质量门禁

- 给定：模型返回缺字段、多答案、重复选项、证据不支持答案或重复题。
- 当：质量检查执行。
- 那么：进入有限修复或淘汰；最终不合格时返回 `AI_OUTPUT_INVALID`，不存在无限重试。

### AC-09 可追踪证据

- 给定：任一道返回给前端的题。
- 当：检查题目来源。
- 那么：至少一个 `source_ref` 指向响应中存在的 `source_id`，包含非空证据片段和位置。

## C. 作答与报告

### AC-10 逐题锁定

- 给定：用户尚未选择答案。
- 当：点击提交当前题。
- 那么：前端不允许提交；选择后提交即锁定，并显示对错、解析和来源。

### AC-11 确定性判分

- 给定：5 或 10 道题及完整作答。
- 当：提交闯关。
- 那么：后端程序计算总题数、正确数、正确率、用时和知识点统计，结果与作答逐项一致。

### AC-12 报告降级

- 给定：客观判分已完成，但报告模型超时或输出非法。
- 当：生成报告。
- 那么：仍返回 `COMPLETED` 和可信基础报告，不修改任何客观统计。

### AC-13 重复提交

- 给定：一个已经完成的闯关。
- 当：重复提交完全相同作答。
- 那么：返回第一次生成的同一报告；提交不同作答则返回 `RUN_ALREADY_COMPLETED`。

## D. 恢复与运维

### AC-14 会话过期

- 给定：会话创建已超过 60 分钟。
- 当：获取或提交会话。
- 那么：返回 HTTP 410 `RUN_EXPIRED`；前端用 24 小时内缓存的输入和配置重新生成。

### AC-15 有边界的失败

- 给定：断网、限流、来源抓取失败、模型超时或非法输出。
- 当：调用 API。
- 那么：返回契约错误码和 `request_id`；前端停止等待并提供对应恢复动作。

### AC-16 健康与就绪

- 给定：服务运行但必要百炼配置缺失。
- 当：访问 `/health` 与 `/ready`。
- 那么：`/health` 返回 200；`/ready` 返回 503 且不发起任何收费请求。

### AC-17 密钥与日志

- 给定：任意成功或失败调用。
- 当：检查小程序产物、响应和后端日志。
- 那么：不存在 API Key、Authorization、完整敏感输入、完整抓取正文或堆栈泄露。

## E. 明确不验收

本版不接受以下功能作为交付要求：登录、历史记录、15 题、知识点确认、关卡地图、动态追题、复习提醒、分享、创作者、排行榜、多人对战和支付。
