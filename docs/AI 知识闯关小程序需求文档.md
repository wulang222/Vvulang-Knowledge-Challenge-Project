# AI 知识闯关小程序

## 需求分析文档

> **一句话产品定义**
>
> 将用户提出的问题、学习主题或提供的资料，转化为有可核验来源、能自适应调关、可复盘分享的 10 分钟知识闯关。

| **项目目标** | 求职作品项目（兼顾后续商业验证）                            |
|--------------|-------------------------------------------------------------|
| **目标人群** | 通用学习人群；首轮覆盖“有问题想快速弄懂”和“有资料想自测”的用户 |
| **MVP 输入** | 一句话问题、学习主题、任意长度纯文本                           |
| **版本日期** | V1.2 · 2026-10-03                                           |

研究范围：需求可靠性 · 竞品格局 · 产品定位 · MVP 需求 · 技术可行性 · 验证方案

# 0. 执行摘要

> **结论：值得做，但必须换一个竞争焦点**
>
> 作为求职作品项目，建议立即推进，综合价值评分 8.7/10；作为面向大众的商业产品，只建议在完成 2 周真实用户验证后继续投入，当前评分 6.4/10。原因是“AI 从资料生成题目”已成为标配，单靠出题无法建立差异化。产品应从“AI 出题工具”升级为“可信、自适应、可复盘的闯关式学习系统”。

## 0.1 核心判断

| **判断**   | **结论**                                                                                               |
|------------|--------------------------------------------------------------------------------------------------------|
| 需求真实   | 主动回忆/练习测试具有较稳定的学习效果；游戏化对动机和行为有小幅但显著的正向影响。[1][2]            |
| 竞争拥挤   | Quizlet、Knowt、Quizgecko、Kahoot、StudyFetch，以及国内快出题、优考试、秒出题等均已覆盖“资料→题目”。   |
| 缺口仍在   | 公开能力中较少同时覆盖：逐题来源证据、按知识点动态调关、错因分类、可执行复习计划、微信原生分享。       |
| MVP 可控   | 首版支持问题/主题/文本输入与受控官方来源检索；只做选择题与判断题，不做视频、开放式网页漫游、多人实时对战或主观题自动评分。 |
| 作品价值高 | 可完整展示输入意图识别、受控 Web RAG、文本解析、证据检索、结构化输出、质量评估与 Agent 工作流。       |

## 0.2 推荐的产品北极星

> **不是“生成了多少题”，而是“用户掌握了多少知识点”**
>
> 北极星指标：每周完成至少一次“生成→闯关→错题复习→二次达标”的有效学习闭环用户数（Weekly Mastery Users，WMU）。

## 0.3 三项必须成立的差异化

- 可信：每道题绑定用户原文或官方来源的标题、发布方、链接/位置与证据片段；无法从已核验来源确认的题不进入题库。

- 自适应：答错不只是展示答案，而是识别错因、降低难度、补一道同知识点变式题；连续正确才通关。

- 可复盘：通关报告不是总分截图，而是知识点掌握度、错误类型、下一次复习时间和一键再练。

# 1. 项目背景与问题定义

## 1.1 背景

学习需求既可能来自长文档、课件和复习提纲，也可能只是一句“RAG 是什么”。用户不应为了达到字数门槛而补写材料：有原文时，平台应优先依据原文；只有问题或主题时，平台应检索可核验的官方资料，再生成练习。无论入口长短，读完后都容易产生“看懂了就是会了”的错觉，因此仍需要低门槛、即时反馈的练习闭环。

微信小程序适合承载碎片化学习：免安装、入口轻、便于通过聊天与群分享挑战结果或学习包。但微信生态只是分发优势，不是产品壁垒；真正的留存来自题目可信度和复习效果。

## 1.2 待解决的核心问题

| **问题**   | **用户现状**                   | **产品回应**                       |
|------------|--------------------------------|------------------------------------|
| 启动难     | 可能只有一个问题，也可能有很长资料 | 自动识别输入意图，补齐可靠来源并生成 5–10 分钟关卡 |
| 掌握感失真 | 阅读时觉得懂，离开原文却答不出 | 以主动回忆替代被动重读             |
| 题目不可信 | AI 题目可能无来源、答案含糊    | 逐题标注用户原文或官方来源、自动校验、问题反馈入口 |
| 答完即结束 | 只有分数，没有下一步           | 错因、薄弱点、复习计划、一键再练   |
| 坚持困难   | 学习反馈慢、过程枯燥           | 关卡、连胜、Boss 题与轻量分享激励  |

## 1.3 学习机制依据

练习测试（retrieval practice）并非单纯的测量工具，它本身能够强化记忆。对 217 项研究的综合分析显示，练习测试总体优于重复学习，并且对保持与迁移均有收益。[1] 因此产品的学习价值应建立在“让用户频繁从记忆中提取答案”，而不是仅把资料摘要得更漂亮。

游戏化可以改善学习动机和行为，但效果受设计质量影响。一项元分析报告游戏化对动机和行为均有显著的小效应，且研究间差异较大。[2] 因此关卡、积分和徽章必须服务于知识掌握，不应以纯签到或刷时长替代学习目标。

## 1.4 项目目标与非目标

| **类型**   | **定义**                                                                   |
|------------|----------------------------------------------------------------------------|
| 产品目标   | 把问题、主题或用户资料转成可信的互动练习，并形成可执行的复习闭环。         |
| 体验目标   | 首次用户可直接输入一句话并开始生成；单关 5–10 分钟。                      |
| 作品目标   | 体现完整产品思维和 AI 工程能力，而不是模型 API 的简单包装。                |
| 首版非目标 | 替代专业考试题库、覆盖所有文件格式、承担正式考试防作弊、实现多人实时竞技。 |

## 1.5 输入与来源策略

- 前端不设置最少或最多字数门槛，不显示“还差多少字”一类阻断提示；一句正常问题也可以提交。
- 后端将输入分类为 `QUESTION`（问题/主题）、`USER_SOURCE`（用户原文/文档）或 `HYBRID`（问题 + 原文），并独立执行内容安全和敏感信息检查。
- `QUESTION`：检索政府、标准组织、大学、论文发布机构或产品官方文档等权威来源，再规划知识点和题目。
- `USER_SOURCE`：以用户原文为主要依据；需要外部补充时只使用可核验的官方来源，并明确区分“用户资料”和“官方补充”。
- `HYBRID`：先回答用户明确提出的学习目标，再在用户原文和官方来源之间建立可追踪的证据集合。
- 若检测到身份证号、密码、密钥、未授权商业机密等敏感信息，保留用户输入但暂停生成，明确指出风险并提供删除/修改入口。
- 若找不到足以支持题目的可靠来源，不用低质量网页凑题；提示用户换个问法、指定来源或补充资料。

# 2. 目标用户、场景与用户任务

## 2.1 人群策略

长期定位为“通用学习人群”，首轮用两个互补入口验证：用户只有一个想弄懂的问题，或已经拥有明确复习资料并希望在短时间内检查掌握程度。统一底座同时覆盖大学生期末复习、职业资格备考、程序员面试准备和企业内部培训。

| **画像**   | **典型身份**    | **核心痛点**                 | **期望任务**                    |
|------------|-----------------|------------------------------|---------------------------------|
| 临考复习者 | 大学生/考证用户 | 复习资料很多，不知重点；时间紧 | 粘贴原文→10 分钟闯关→薄弱点再练 |
| 技能学习者 | 程序员/求职者   | 概念多、容易看懂但说不出     | 粘贴笔记→场景题→错因复盘        |
| 快速求知者 | 学生/职场用户   | 只有一个问题，不知从哪里学起 | 输入问题→检索官方资料→立即闯关   |
| 知识发布者 | 老师/培训负责人 | 出题、整理答案和统计耗时     | 生成学习包→人工审核→分享给学员  |

## 2.2 Jobs To Be Done

- 当我拿到一份很长的资料时，我希望系统快速告诉我哪些知识点最重要，并立即用题目检查我是否真的掌握。

- 当我只有一句问题或一个主题时，我希望系统主动找到可靠资料并说明出处，而不是要求我先写满一段文字。

- 当我答错时，我希望知道自己为什么错、题目依据来自哪份用户原文或官方资料，以及下一步练什么，而不只是看到正确答案。

- 当我完成学习时，我希望得到一张既能看懂成果、又能继续行动的报告，并可方便地分享给同学或同事。

## 2.3 核心场景

| **场景**      | **触发**          | **任务**         | **结果**                 |
|---------------|-------------------|------------------|--------------------------|
| S1 快速自测   | 粘贴课堂/面试笔记 | 5 分钟内开始答题 | 是否值得继续复习         |
| S0 问题闯关   | 输入“RAG 是什么”  | 检索官方资料并生成关卡 | 快速建立概念与可追溯依据 |
| S2 原文闯关   | 粘贴任意长度文本   | 按知识点逐关推进 | 掌握度与薄弱点           |
| S3 错题回炉   | 进入历史报告      | 只练未掌握知识点 | 二次达标                 |
| S4 学习包分享 | 分享关卡或报告卡  | 好友打开并挑战   | 传播与对比，但不泄露原文 |

# 3. 市场与竞品调研

## 3.1 竞品格局

现有产品大致分为三类：第一类是 Quizlet、Knowt、Quizgecko、StudyFetch 等面向学生的 AI 学习平台；第二类是 Kahoot 等以互动课堂与游戏化为优势的平台；第三类是快出题、优考试、秒出题等面向考试、培训和组织管理的国内工具。它们共同证明“资料转题”存在需求，也意味着该能力已经难以单独构成卖点。

| **竞品**   | **核心路径**             | **公开优势**                   | **可切入空间**                             |
|------------|--------------------------|--------------------------------|--------------------------------------------|
| Quizlet    | 文档/文本→练习测试       | 题型和长度可选、强弱项反馈     | 未突出关卡、逐题证据与分享报告             |
| Knowt      | 多格式资料→题卡/测验     | 间隔重复、AI 学伴、错题解释    | 未突出知识点关卡地图与证据链               |
| Quizgecko  | 资料→课程/题卡/笔记      | 可编辑、调难度、学习进度       | 游戏化与微信传播不突出                     |
| Kahoot     | 网页/PDF/手写笔记→互动题 | 课堂游戏与群体参与强           | 个人复习闭环和细粒度复盘弱                 |
| StudyFetch | 课程资料→笔记/游戏/路径  | AI Tutor、Arcade、个性化路径   | 产品宽而重，中文微信轻场景不是重点         |
| 快出题     | 多格式资料→试卷          | 答案解析、组卷、阅卷、发布链接 | 偏出题/考试，个人闯关与复盘弱              |
| 优考试     | 题库/培训/考试           | 闯关、证书、分析报表           | 偏 B 端组织考试，个人资料即时学习不是核心  |
| 秒出题AI   | Word/PDF→多题型考试      | 小程序发布、微信群分发         | 详细错因、自适应和证据链不突出             |
| 题喵喵     | 跨端刷题系统             | 多题型、错题本、统计、AI 导题  | 开源实现强，但学习效果闭环与可信生成可深化 |

## 3.3 用户反馈暴露的机会

公开用户讨论中反复出现两类问题：一是 AI 生成的问题可能超出原始材料或不符合教师的出题风格；二是免费额度与付费价值不够透明。[13] 这提示本项目应把“依据原文生成”和“生成前可配置”放在首屏，而不是把更多题型当作第一卖点。

## 5.4 不建议首版实现的功能

- 无边界全网自动浏览：首版只做受控检索，优先官方/权威来源、固定工具白名单和来源门禁，不允许 Agent 任意漫游网页。

- 视频解析与 AI 生图：成本、时延和质量验证复杂，不能证明核心价值。

- 多人实时对战与排行榜：需要匹配、房间、断线重连和反作弊，且可能弱化个人掌握目标。

- 主观题自动评分：评价标准不稳，容易引发信任问题；首版仅保留自评或 AI 参考答案。

- 复杂会员体系：先验证留存和成本，再设计付费墙。

# 6. MVP 范围与功能需求

## 6.1 核心用户流程

1. **输入学习目标**：输入一句问题、主题，或粘贴任意长度原文
2. **识别来源策略**：后端判断使用用户原文、官方检索或混合来源，并执行敏感信息检查
3. **确认范围**：预览知识点、来源类型与参数
4. **生成关卡**：完成来源绑定与质量检查
5. **互动答题**：即时解析并动态补关
6. **复盘再练**：查看报告、错题并分享

## 6.2 MVP 功能清单

| **优先级** | **模块**   | **需求说明**                                           | **边界/备注**             |
|------------|------------|--------------------------------------------------------|---------------------------|
| P0         | 账号与会话 | 微信授权登录；允许先体验后登录；保存生成任务与进度     | 降低首次使用门槛          |
| P0         | 学习输入   | 接受一句问题、主题或任意长度纯文本；前端不设字数门槛 | 超长内容由后端分块/异步处理 |
| P0         | 来源路由   | 判断问题/原文/混合模式；无原文时检索官方资料；逐题记录来源 | 受控检索，不开放任意浏览   |
| P0         | 知识点预览 | 生成 5–12 个知识点；用户可删除、合并、改名、设置重点   | 先确认再出题，减少浪费    |
| P0         | 闯关配置   | 题量 5/10/15；难度基础/进阶；题型单选/判断             | 默认 10 题、混合难度      |
| P0         | 题目生成   | 每题包含题干、选项、答案、解析、知识点、难度、来源类型、标题、发布方、链接/位置与证据片段 | 结构化校验后入库 |
| P0         | 互动答题   | 选择后即时判定；无论对错都给简析；可查看来源证据       | 不可在作答前暴露答案      |
| P0         | 动态补关   | 答错生成/抽取同知识点变式题；连续正确 2 次视为暂时掌握 | 最多补 2 题，防止无限循环 |
| P0         | 通关报告   | 总分、掌握度、薄弱知识点、错因、建议复习顺序、一键再练 | 报告必须可行动            |
| P0         | 历史与错题 | 查看历史学习包、继续未完成关卡、只练错题               | 保留题目版本和来源        |
| P0         | 问题反馈   | 标记题目有误/答案不清/超出资料，并记录修正             | 构成质量数据              |
| P1         | 分享卡     | 生成带小程序码的报告卡或挑战卡；隐藏原始资料           | 分享前可选择公开范围      |
| P1         | 复习提醒   | 根据掌握度生成 1/3/7 天复习计划                        | 用户主动订阅消息          |
| P1         | 创作者模式 | 发布经人工审核的学习包，查看完成率和难题               | 老师/培训扩展入口         |
| P1         | 文件输入   | 支持 PDF/DOCX 上传、解析与页码级证据定位                | 核心文本闭环稳定后实现    |
| P2         | 多人对战   | 好友房、实时题目、排行榜、赛后报告                     | 核心闭环稳定后            |

## 6.3 关键交互规则

- 生成前：不以字数阻断；必须展示预计题量、知识点范围、来源策略和预计等待时间，允许用户取消。

- 生成中：使用分阶段进度（理解输入→检查安全→整理/检索来源→规划考点→生成与质检），不要只显示无限转圈或虚假百分比。

- 答题中：一次只呈现一题；提交后锁定本题选择，再显示结果、简析和证据。

- 解析中：把“为什么正确”“其他选项为什么错”“来源依据”分开，默认简洁，可展开详情。

- 通关判定：完成基础题不等于掌握；薄弱知识点需通过补关或二次复习才标记达标。

- 失败处理：文档解析失败、模型超时、题目质检失败均提供可理解原因与重试入口，不丢失原始任务。

## 6.4 关键页面

| **页面**   | **主要内容**                         | **体验目标**     |
|------------|--------------------------------------|------------------|
| 首页       | 问题/主题/原文输入框、示例入口、场景模板、最近学习 | 一句话也能开始 |
| 知识点确认 | 知识点列表、重要度、难度、题量       | 给用户控制感     |
| 生成进度   | 阶段进度、耗时提示、取消/后台生成    | 降低等待焦虑     |
| 闯关页     | 题目、选项、进度、连胜、提交         | 专注且不卡顿     |
| 解析页     | 正确性、简析、错因、证据、下一题     | 建立可信度       |
| 通关报告   | 掌握雷达/列表、错题、复习计划、分享  | 驱动二次行动     |
| 学习中心   | 历史学习包、错题、待复习、数据趋势   | 长期留存         |

# 7. AI 生成与质量控制需求

## 7.1 生成流水线

1. **分类与安全检查**：识别问题/原文/混合输入，检测敏感信息与不适宜内容
2. **来源获取**：解析用户资料；没有资料或需要补充时，检索官方/权威来源
3. **来源归一化**：去重、分块并保留标题、发布方、URL、发布日期/检索时间及原文位置
4. **规划**：确定知识点、来源覆盖与题型分布
5. **生成**：输出结构化题目对象
6. **质检**：检查证据、一致性、来源等级与重复内容

## 7.2 题目数据结构（最小字段）

| **字段**           | **含义**                   | **示例**                     |
|--------------------|----------------------------|------------------------------|
| question_id        | 题目唯一标识               | UUID                         |
| knowledge_point_id | 所属知识点                 | KP-03                        |
| type               | single_choice / true_false | single_choice                |
| stem               | 题干                       | 以下关于……正确的是？         |
| options            | 选项列表                   | A/B/C/D                      |
| correct_answer     | 标准答案                   | B                            |
| explanation        | 答案解释                   | 为什么正确及干扰项说明       |
| source             | 来源元数据                 | 类型、标题、发布方、URL/文件位置、段落、证据片段、检索时间 |
| difficulty         | 难度等级                   | 1–3                          |
| quality_flags      | 质检结果                   | grounded=true, ambiguity=low |

## 7.3 质量门禁

| **门禁**   | **规则**                                     | **处理**                   |
|------------|----------------------------------------------|----------------------------|
| 来源约束   | 正确答案必须可被用户原文或已核验官方来源直接支持 | 无证据则丢弃/重生成      |
| 唯一答案   | 单选题只能有一个最佳答案                     | 二次模型或规则校验         |
| 干扰项质量 | 看似合理但可被原文排除；不得纯文字长度暗示   | 检测重复、包含关系和绝对词 |
| 范围一致   | 不得使用未进入本次证据集合的模型常识判题；外部事实必须有官方来源 | 无来源事实直接淘汰 |
| 来源透明   | 用户原文、官方检索与混合来源必须有明确标签；外链保留标题和发布方 | 来源不完整不得发布 |
| 语言清晰   | 避免否定套否定、指代不明和歧义               | 歧义评分超阈值重写         |
| 难度可解释 | 基础=直接回忆；进阶=比较/应用；Boss=跨知识点 | 基于 Bloom 层级近似标注    |
| 去重       | 题干和考点不得高度重复                       | 语义相似度+答案分布检查    |

## 7.4 自适应闯关规则（MVP）

| **行为**                | **系统动作**                       | **掌握判定**        |
|-------------------------|------------------------------------|---------------------|
| 首次正确且高置信        | 进入下一知识点                     | +2 掌握分           |
| 首次正确但用时过长/改答 | 追加一道同知识点题                 | +1 掌握分           |
| 答错                    | 展示错因与证据，追加更基础变式题   | -1 掌握分           |
| 补题正确                | 再给一道等难度确认题               | 连续 2 次正确才达标 |
| 补题再次错误            | 标记薄弱点，先跳过，进入报告待复习 | 避免挫败和无限循环  |

## 7.5 可信度设计

- 题目卡显示“依据：用户资料第 X 页/段”或“依据：某官方文档（发布方）”，解析后可展开证据并访问来源。

- AI 生成内容在界面和导出/分享内容中提供清晰标识；公开传播时遵循生成合成内容标识要求。[12]

- 用户反馈后的题目立即从个人后续练习中下线，进入待复核状态。

- 报告中区分“已掌握”“暂时掌握”“需要复习”，避免用一次答对夸大结果。

- 结果总览：完成题数、正确率、用时、连续正确次数。

- 错因分布：概念混淆、记忆缺失、审题失误、无把握猜测。

# 10. 技术可行性与建议架构

## 10.1 可行性判断

该 MVP 技术风险总体可控。首版纯文本可以直接分块并保留字符位置；结构化输出可通过 Pydantic 模型校验题目字段，并保留解析错误用于重试。[11] 后续扩展 PDF/DOCX 时，LangChain 也支持将 PDF 页面转为带 source/page 元数据的 Document，再用 RecursiveCharacterTextSplitter 分块并保留起始位置。[10] 这为“逐题证据”和“稳定题目对象”提供了成熟基础。

## 10.2 推荐架构

| **层**   | **建议**                                            | **职责/理由**                                         |
|----------|-----------------------------------------------------|-------------------------------------------------------|
| 小程序端 | Uni-app + Vue 3                                     | 利用已有 Vue/Uni-app 经验；微信登录、上传、答题、分享 |
| 业务后端 | Java 21 + Spring Boot                               | 用户、任务、题库、答题、报告、权限、支付预留          |
| AI 服务  | Python + FastAPI + LangChain/LangGraph              | 输入路由、受控 Web RAG、文档解析、知识点规划、题目生成与质检 |
| 数据     | MySQL + Redis                                       | 持久数据、任务状态、限流、热点缓存                    |
| 文件     | OSS/MinIO 私有桶                                    | 原始文档和导出卡片；使用临时授权访问                  |
| 检索     | 用户资料分块 + 官方来源搜索/抓取 + 统一证据索引；长文档再接 Milvus | 先保证来源可追溯，再按规模升级 |
| 异步     | RabbitMQ/Redis Stream（二选一）                     | 解析与生成任务异步化、重试和削峰                      |
| 模型     | 支持 Qwen/DeepSeek/OpenAI 兼容接口的适配层          | 可按质量、成本和地域切换                              |

## 10.3 服务边界

| **服务**       | **负责**                                     | **不负责**                   |
|----------------|----------------------------------------------|------------------------------|
| Java 业务服务  | 鉴权、订单、资料元数据、闯关状态、报告、审计 | 模型提示词和文档分块细节     |
| Python AI 服务 | 解析、分块、检索、结构化生成、质量检查       | 用户账户、支付和最终权限判断 |
| 小程序端       | 交互、状态展示、文件选择、分享               | 可信答案生成与敏感权限决策   |

## 10.4 成本与性能控制

- 先生成知识点与题目规划，再按关卡批量生成，避免每题单独调用模型。

- 短文本不进入向量库；长文档只索引有效正文，表目录、页眉页脚和重复段落先清洗。

- 一句话问题直接进入检索规划，不要求补足字数；优先命中官方域名和权威发布机构，并缓存检索结果与抓取时间。

- 题目和证据一并缓存；同一资料重新配置时复用解析与分块结果。

- 使用小模型做分类、去重和格式修复，大模型只承担规划与高质量生成。

- 为每个任务设置 token、重试次数和最大题量硬上限；失败后局部重试而非整份重做。
